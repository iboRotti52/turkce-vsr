## 2. BU OTURUMUN ANA BULGUSU

### Dublaj filtresi dublaj ölçmüyordu, gürültü ölçüyordu

`pipeline.py` → `crop_segments` her **segment** için ağız-açıklığı ile ses enerjisi
korelasyonunu hesaplayıp `DUB_CORR_THRESHOLD = 0.15` altındakileri eliyordu.

Sorun örneklem büyüklüğünde: segmentler 1-6 saniye = **25-150 kare**. Bu n'de iki bağımsız
serinin korelasyonunun standart sapması ≈ **0.122**. Yani 0.15'lik eşik, saf gürültünün
1.2σ'sı — filtre karar vermiyor, zar atıyordu.

**Nasıl doğrulandı:** 20.000 rastgele seri çiftiyle null dağılım simüle edildi, gerçek
ölçülen dağılımla karşılaştırıldı — ayırt edilemedi. Ölçülen dağılımın %41'i negatif
korelasyondu, tepesi tam sıfırdaydı.

**Sonuç:** TEDx konuşmaları (dublajsız oldukları kesin) segmentlerinin ~%84'ünü bu yüzden
kaybediyordu.

### Çözüm: karar video seviyesine taşındı

- `video_dub_score()` — korelasyon tüm video boyunca (n = 30-140 bin kare → null σ ≈ 0.006)
- `dub_esigi(n) = 3.0 / sqrt(n)` — sabit sayı yerine **anlamlılık**. Örnek sayısı yetersizse
  eşik kendiliğinden erişilemez olur (`n < 5` → 1.0 döner).
- Video eşiği geçemezse **tüm videosu** elenir (`red["video_dublajli"]`), segment segment değil.
- Segment seviyesinde artık yalnız yüz kontrolleri var.

## 3. KOD DEĞİŞİKLİKLERİ (hepsi doğrulandı)

### `pipeline.py`

| Ne | Detay |
|---|---|
| `_timed(timings, stage)` | context manager, aşama süresi ölçer (2 ondalık, `finally` ile hata durumunda da yazar) |
| `_gpu_share(timings)` | `asr / toplam` oranı |
| `_corr(faces, audio, sr, t0, t1)` | ortak korelasyon çekirdeği, `(skor, n)` döner |
| `dub_esigi(n)` | `3/sqrt(n)`; `n < MIN_SEG_DUB_FRAMES` ise `1.0` |
| `video_dub_score(faces, audio, sr)` | tüm video üzerinde `_corr` |
| `seg_dub_score(...)` | **artık kabul kararında kullanılmıyor**, yalnız teşhis/meta.json |
| `crop_segments(...)` | `dict` döner (red sayaçları). Eleme sebepleri: `kabul`, `yuz_yok`, `yuz_kucuk`, `video_dublajli`. `DUB_CORR_THRESHOLD` **artık kullanılmıyor**. |
| `process_video(...)` | sonuç dict'ine `timings`, `gpu_share`, `red` eklendi |

`red` sözlüğünde ayrıca teşhis alanları: `video_dub_skor`, `video_dub_esik`, `video_dub_n`,
ve `dub_<n>` histogram kovaları (0.05 genişlik, **negatif olabilir**).

### `modal_pipeline.py`

| Ne | Detay |
|---|---|

| `timeout=5400` | (eski 3600) CPU-only ASR ~5× yavaş |

| `main(..., bekle: bool = True)` | `--no-bekle` → `orchestrate.spawn()`, çağrı kimliğini basar ve `.son_cagri`'ye yazar |
| `main(sources, limit, out)` | dosya/limit/çıktı parametreleri |

```

```

**CPU/GPU'yu iki Modal fonksiyonuna bölmek düşünüldü ve BİLEREK YAPILMADI.** Hesap:
bölme $0.037, CPU-only $0.039 — fark %6. ASR toplam sürenin küçük bir kısmı olduğu için
(Amdahl) iki fonksiyon + volume commit/reload dansı + yeni hata yüzeyi bu kadarına değmez.

### Asenkron koşu (laptop kapatılabilir)

**Sorun:** `@app.local_entrypoint()` koordinatörü **yerelde** çalıştırıyordu. `starmap`'i
çağıran ve 15 işçiyi bekleyen süreç laptop'taydı; laptop/kabuk kapanınca hepsi iptal oluyordu.
`--detach` bunu çözmüyor — Modal'ın kendi uyarısı: yalnız **son tetiklenen** fonksiyonu
ayakta tutar, bir `starmap`'in N çağrısını değil.

**Çözüm:** fan-out `orchestrate` adlı bir Modal fonksiyonuna taşındı. `spawn()` ile
tetiklenip yerel süreç çıkıyor; tetikleyen taraf artık sunucu.

```bash
# başlat (laptop kapatılabilir)
MODAL_PROFILE=yenihesap ./.venv/bin/modal run --detach modal_pipeline.py::main \
    --sources sources.txt --out cikti.json --no-bekle

# sonra, istediğin zaman
MODAL_PROFILE=yenihesap ./.venv/bin/python sonuc.py "" cikti.json
```
